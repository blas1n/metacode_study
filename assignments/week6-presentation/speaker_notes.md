## 슬라이드별 멘트

### 1. Cover

> 안녕하세요. **BSVibe** 의 김동휘입니다. 한 줄 태그라인이 곧 발표 메시지예요 — "믿음이 아닌, 증명."

(짧게. 청중에 바로 다음 슬라이드로.)

### 2. 한 사람이, 여러 제품을 (Problem)

> 1인 회사를 운영하면서 제가 겪은 진짜 비용은 작업 자체보다 **컨텍스트 관리** 였어요.
> - 같은 결정을 두 번, 세 번 다시 내리고
> - AI 가 만든 결과를 처음부터 다시 검증해야 하고
> - 잡일이 진짜 일을 가립니다.
>
> 그래서 "AI 가 결과를 믿을 수 있게 돌려주기만 해도 시간이 진짜 줄어든다" 가 출발점이었어요.

### 3. BSVibe 가 답하는 한 줄 (Solution)

> 그 문제에 대한 답이 이 한 줄입니다.
> **한 줄 던지면 AI 가 일하고, 스스로 검증하고, 사람이 읽을 수 있는 증거와 함께 돌려준다. 한 번 바로잡으면 같은 실수는 두 번 없다.**
>
> 핵심 차별점 세 가지를 강조 — 검증된 결과 / 같은 실수는 한 번만 / 혼자서 여러 제품.

### 4. 어떻게 작동하나요

> 네 단계로 진행됩니다.
>
> 1. **던지세요** — 한 줄로 충분. 이메일이나 GitHub 이슈가 들어와도 자리에 없는 동안 시작돼요.
> 2. **AI 가 일합니다** — 계획·실행·검증 루프. 진짜 갈림길에서만 물어보고, 답을 받으면 그 자리에서 이어갑니다.
> 3. **증거를 냅니다** — "끝났다" 를 그냥 받아들이지 않아요. 무엇을 어떻게 확인했는지 항상 같이 옵니다.
> 4. **기억합니다** — 한 번 바로잡은 것이 쌓여서, 다음부터 같은 실수는 알아서 피해요.

### 5. Brief

> 첫 화면이 Brief 예요. 운영 콘솔 같은 게 아니라, **사람이 말하듯 설명하는 현황판** 입니다.
> 무엇이 진행 중이고 무엇이 결정을 기다리는지 5초면 압니다. JIRA · ticket 이 아니라 평범한 한국말로.

### 6. Delivery Report (유리상자)

> 결과는 한 장 짜리 Delivery Report 로 옵니다. Intent / Work / Checks / Verdict / Artifact — 5개 섹션.
>
> 강조 포인트: **"검증 없이 verified 라고 못 박는 길이 코드 자체에서 막혀 있다"** — `verification_contract` 라는 데이터 모델로 강제됩니다.
> AI 가 임의로 통과 처리 못 함 → founder 가 결과를 진짜 신뢰 가능.

### 7. Decide

> 갈림길은 두 종류입니다.
> - 답이 정해진 갈림길 — AI 가 알아서 끝까지 진행
> - 취향·범위·방향 같은 founder 만 정할 수 있는 갈림길 — 그때만 올라옵니다
>
> 답하는 순간 그 자리에서 이어가요 — context switch 비용 0. 그리고 그 선택은 **resolved decision** 으로 기억돼 다음에 비슷한 케이스가 오면 자동으로 재사용됩니다.

### 8. Safe Mode

> 푸시 · 머지 · 이메일 발송 같은 **되돌리기 어려운 작업** 은 승인 전엔 밖으로 나가지 않습니다.
> 안전한 작업은 자동, 위험한 것만 보류 — founder 가 진짜 신경 써야 할 결정에 시간을 쓰도록 설계.

### 9. Under the hood

> 보이지 않는 곳에서 돌아가는 4가지:
> - 실행 엔진 — plan-act-verify loop
> - 비용 최적 라우팅 — 로컬·클라우드 LLM 자동 선택
> - 안전 가드레일 — Safe Mode 외에 검증 계약, 권한 분리
> - 기억·개인화 — vault + knowledge graph
>
> 결과만 보이고, 나머지는 안에서 돌아갑니다.

### 10. Knowledge Graph (메모리 구조)

> "기억합니다" 의 기술적 실체. founder 가 한 모든 결정과 AI 의 모든 관찰이 **하나의 지식 그래프** 로 쌓입니다.
> - 날 것의 관찰 (garden notes) 이 일정 횟수 반복되면 canonical concept 으로 승격
> - 결정과 거절된 접근이 따로 인덱싱돼 다음 작업에 자동 인용
> - **Hybrid retrieval** — vector 의미 검색 + BM25 키워드 + 그래프 1-hop 이웃을 RRF 로 결합
>
> 잘못 학습한 노드는 Inside view 에서 한 클릭 retract — 30 초 안에 undo 가능합니다.

### 11. 어디서든, 무엇과도

> 웹 기반이라 **설치 없이 브라우저** 만 있으면 데스크톱이든 모바일이든 같은 경험.
> 쓰던 도구를 그대로 연결 — GitHub · Slack · Notion · Linear · Discord · Sentry · Telegram · Email. OAuth 또는 PAT 한 번이면 됩니다.

### 12. 기술 스택

> 부트캠프 청중 대상이라 빠르게: Next.js PWA + FastAPI + pgvector + NetworkX. 임베딩은 멀티링구얼 bge-m3, 답변 LLM 은 로컬 ollama (llama3.2 / qwen3-coder) + 클라우드 fallback. 모노레포 + 1인 운영 + Mac Mini self-host.
>
> 강조: **Hybrid retrieval (Vector + BM25 + Graph RRF)** — 단순 vector 검색이 아니라 세 갈래 결합. 다음 슬라이드 데모에서 직접 보입니다.

### 13. 라이브 데모 cue

> (app.bsvibe.dev 로 전환 — 가능하면 라이브, 어려우면 녹화)
>
> 네 가지 흐름 보여드릴게요.
> 1. **Inside view** — 워크스페이스가 학습한 지식 그래프. 노드 클릭 → inspector 에 의미·출처·연관 노드
> 2. **Brief** — 오늘 들어온 일과 결과를 한 줄씩
> 3. **Knowledge chat** — 질문을 던지면 grounding 인용과 함께 답변. 단일 LLM 호출의 KnowledgeAnswerOrchestrator 가 돌아갑니다
> 4. **Retract** — 잘못 학습한 노드 한 클릭 retract → 30 초 undo toast → tombstone
>
> (한 흐름당 15–25 초. 너무 길게 끌지 말 것.)

### 14. Closing — 한 줄 약속

> 다시 한 줄로 돌아가면 — **감독할 일이 시간이 지날수록 줄어듭니다.** 그게 BSVibe 의 단 하나의 약속이에요.
>
> 감사합니다. 질문 받겠습니다.

## Q&A 대응표

가능성 높은 질문 + 짧은 답안.

| 질문 유형 | 예상 질문 | 답안 핵심 |
|---|---|---|
| **기술** | 왜 streamlit 안 쓰고 Next.js 직접 만들었나요? | 모바일 PWA + i18n + 인증 모두 필요해서. streamlit 으로는 운영 product 가 안 됨 |
| **기술** | LLM 모델은 어떻게 골라요? | 작업 종류로 분류 (cheap/heavy/local/cloud) → 비용·지연 가중치로 자동 선택. 사용자가 워크스페이스 정책으로 덮어쓰기 가능 |
| **기술** | Hybrid retrieval 의 RRF 가 뭔가요? | Reciprocal Rank Fusion — 여러 검색의 rank 를 1/(60+rank) 점수로 합산. 표준 RRF 논문(k=60). 세 갈래 (vector·BM25·graph) 결합 |
| **기술** | bge-m3 왜? text-embedding-3-small 안 써요? | 한국어 질문 ↔ 영문 코드 cross-lingual 갭 줄이려고. bge-m3 가 100+ 언어 multilingual 임베딩, 같은 의미 KO/EN 의 sim 갭이 절반으로 |
| **제품** | 다른 founder OS (Notion AI · Granola · Reflect) 와 뭐가 달라요? | 메모/노트 도구가 아니라 **agent가 실제 작업을 하고 그 결과에 증거가 붙는** 도구. Delivery Report 가 핵심. |
| **제품** | 진짜 1인이서 만든 거예요? 운영 비용은? | 네. Mac Mini self-host + Vercel free + Supabase free + 로컬 ollama → 월 ~10달러 (도메인 + 클라우드 LLM 일부 사용 시) |
| **제품** | 사용자 데이터는요? | Workspace-scoped vault — 워크스페이스 단위로 격리. 모든 vault note 와 그래프는 founder 본인의 데이터. 다른 워크스페이스 접근 불가 |
| **품질** | "검증" 이 LLM-as-judge 면 그것도 환각 가능하지 않나요? | 맞아요. 그래서 verification contract 가 **실행 가능한 검증** 을 강제 — `pytest` exit code · `ruff` 통과 여부 · 외부 API 응답 같은 결정적 신호. LLM judge 는 보조용 |
| **품질** | 잘못된 학습 retract 하면 이전 답변은? | 새 retrieval 부터 그 노드 제외. 이전 Delivery Report 들은 그대로 (audit trail) — "이때는 이렇게 답했다" 가 보존. tombstone 만 추가 |
| **로드맵** | 출시는 언제? | 현재 self-host beta, 한 달 안에 close beta 단위로 외부 founder 5명 모집 예정 |
| **로드맵** | 가격은? | 보류 — 1인이 여러 제품 굴리는 데 맞는 단순한 가격 다듬는 중. 지금은 무료로 시작 가능 |

1. **슬라이드 11 (어디서든)** — 데모에서 보여줄 수 있음 → 1분 절약
2. **슬라이드 12 (기술 스택)** — Q&A 에서 받으면 그때 풀기 → 45초 절약
3. **슬라이드 8 (Safe Mode)** 의 멘트 단축 — 한 줄로 "되돌리기 어려운 작업은 승인 전엔 안 나갑니다"

3개 cut 하면 약 2.5분 절약 — 10분에서 7-8분으로 압축 가능.

1. **슬라이드 6 (Delivery Report)** 에서 실제 Delivery Report 화면 띄워 한 섹션씩 짚기 → +30초
