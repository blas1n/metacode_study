# 발표자 노트 (BSVibe · 최종 발표)

청중: 메타코드 부트캠프 — 학우 + 강사. **기술 용어 최대한 풀어** 친근한 톤. 전문어가 꼭 필요하면 한 번씩 풀어 설명.

**총 시간**: 전체 20–25분 (발표 15분 + Q&A 5~10분). 슬라이드 14장.

**표현 원칙**: 각 surface (요약 · 전달물 리포트 · 결정 · 지식 · 스킬) 슬라이드에 실제 화면 스크린샷을 인라인으로 붙임 → 청중이 "지금 설명하는 게 이 화면" 을 즉시 연결. 별도 스토리보드 슬라이드는 제거.

용어 가이드 (슬라이드 / 노트 / 데모 통일 — PWA i18n `messages/ko.json` 의 공식 한국어 번역 사용):

UI 화면 이름 (i18n 공식):
- Brief → **요약**
- Delivery Report → **전달물 리포트**
- Decide / Decisions → **결정**
- Safe Mode → **안전 모드**
- Inside / Knowledge → **지식** 화면
- `+ Direct` compose → **다이렉트**
- Retract → **철회**
- Undo → **되돌리기**
- Direction → **방향**

도메인 용어 (자연어로 풀어 설명):
- proposal → "안건" · "결정거리"
- deliverable → "전달물"
- run → "작업"
- working / needs you / stream → "지금 작업 중 / 결정 대기 / 지난 작업"
- garden notes → "관찰 메모"
- canonical concept → "표준 개념"
- resolved decision → "결정 답안"
- negative pattern → "거절 패턴"
- verification_contract → "검증 약속"
- hybrid retrieval / RRF → "세 갈래 검색 결합"
- executor worker → "내 컴퓨터의 도우미"
- masthead / verdict chip → "헤더 / 판정 표시"
- ontology / canonicalization → "지식 구조 / 정리·통합"

## 슬라이드별 멘트

### 1. Cover

> 안녕하세요. **BSVibe** 의 김동휘입니다. 한 줄 태그라인이 곧 발표 메시지예요 — "믿음이 아닌, 증명."

### 2. 한 사람이, 여러 제품을

> 1인 회사를 운영하면서 제가 겪은 진짜 비용은 작업 자체보다 **머릿속 정리** 였어요.
> - 같은 결정을 두 번, 세 번 다시 내리고
> - AI 가 만든 결과를 처음부터 다시 확인해야 하고
> - 잡일이 진짜 일을 가립니다.
>
> "AI 가 결과를 믿을 수 있게 돌려주기만 해도 시간이 진짜 줄어든다" 가 출발점이었어요.

### 3. BSVibe 가 답하는 한 줄

> 그 문제에 대한 답이 이 한 줄입니다.
> **한 줄 던지면 AI 가 일하고, 스스로 확인하고, 사람이 읽을 수 있는 근거와 함께 돌려준다. 한 번 바로잡으면 같은 실수는 두 번 없다.**
>
> 차별점 세 가지 — 검증된 결과 / 같은 실수는 한 번만 / 혼자서 여러 제품.

### 4. 어떻게 작동하나요

> 네 단계예요. 오른쪽 이미지는 실제 **다이렉트** 입력창 — 한 줄 던지는 게 이렇게 생겼습니다.
>
> 1. **던지세요** — **다이렉트** 버튼으로 한 줄. 메일이나 GitHub 이슈가 들어와도 자리에 없는 동안 시작돼요.
> 2. **AI 가 일합니다** — 계획, 실행, 확인을 반복. 진짜 갈림길에서만 물어보고, 답을 받으면 그 자리에서 이어갑니다.
> 3. **근거를 냅니다** — "끝났다" 는 그냥 받아들이지 않아요. "이 작업은 이렇게 확인하겠다" 가 데이터로 강제됩니다.
> 4. **기억합니다** — 한 번 바로잡은 것이 쌓여서, 다음부터 같은 실수는 알아서 피해요.

### 5. 요약 — 작업 한눈에

> 로그인하면 첫 화면이 **요약** 이에요 — 오른쪽 스크린샷 그대로. **운영 콘솔이 아니라 사람이 말하듯 설명하는 현황판**.
>
> 세 줄로 정리됩니다 — 지금 작업 중, 결정 대기 (갈림길에서 올라온 안건 + 밖으로 내보내기 전 승인 대기), 지난 작업 (끝난 일과 전달물 시간 순).
>
> 처리 안 된 것이 모두 한 화면에 모이는 게 핵심 — 티켓 도구랑 다른 점.

### 6. 전달물 리포트 — 유리상자

> 결과는 한 장 짜리 **전달물 리포트** 로 옵니다 — 오른쪽 이미지가 실제 리포트 화면. 다섯 블록 — 헤더 / 요청 / 만든 것 / 어떻게 확인했나 / 변경 코드.
>
> 강조 포인트: **"만든 것"** 이 진짜 산출물 — 만든 파일의 내용이 곧장 화면에 보입니다. 그리고 **"어떻게 확인했나"** 가 핵심 — 사전에 "이 작업은 이렇게 확인하겠다" 약속을 해두고, 그 약속을 실제로 실행한 결과를 보여줍니다. 확인 없이 통과라고 못 박는 길이 코드 자체에서 막혀 있어요.

### 7. 결정

> 오른쪽 이미지가 실제 **결정 대기** 목록이에요. 갈림길은 두 종류.
> - 답이 정해진 갈림길 — AI 가 알아서 끝까지 진행
> - 취향·범위·방향 같은 사용자만 정할 수 있는 갈림길 — 그때만 올라옵니다
>
> 중요한 부분 — AI 가 단순히 "어떻게 할까요?" 라고 묻기만 하는 게 아니라 **답안 후보를 먼저 만들어서 같이 제시** 해요. 사용자는 그 중 하나를 고르거나, 마음에 안 들면 **직접 입력** 으로 답할 수 있어요.
>
> 답하는 순간 그 자리에서 이어가요. 그리고 그 선택은 **결정 답안** 으로 기억돼 다음 비슷한 케이스에 자동 재사용됩니다.

### 8. 안전 모드

> 푸시 · 머지 · 메일 발송 같은 **되돌리기 어려운 작업** 은 승인 전엔 밖으로 나가지 않아요.
> 안전한 작업은 자동, 위험한 것만 보류 — 요약 화면의 결정 대기 줄에 모입니다. 사용자가 진짜 신경 써야 할 결정에만 시간을 쓰도록.

### 9. 쓰던 LLM 도구를 그대로

> 흥미로운 부분 하나. bsvibe 는 LLM 을 자체 제공하지 않고, **사용자가 이미 쓰는 도구** 를 그대로 결합합니다.
>
> 지원 도구 — Claude Code, OpenAI Codex, OpenCode. 사용자 컴퓨터에서 한 줄 명령으로 작은 도우미를 띄우면 그 도우미가 bsvibe 와 연결되고, 받은 작업을 사용자 컴퓨터의 도구로 실행해요.
>
> 효과:
> - 사용자가 이미 쓰던 구독·세팅이 그대로 살아있음
> - bsvibe 가 LLM 비용을 따로 받지 않음 (사용자가 이미 내고 있는 거니까)
> - 도구마다 강점이 다르면 작업 종류별로 도우미를 여러 개 띄울 수 있음
>
> 한 줄로 정리 — **bsvibe = 작업 배분 + 결과 확인 + 기억. LLM 선택은 사용자의 몫.**

### 10. 안에서 어떻게 굴러가나 — 소프트웨어 구조

> 부트캠프 청중에 맞춰 시스템 구조를 한 장으로 정리했어요.
>
> **위에서 아래로 요청이 흐릅니다:**
> - **클라이언트** — Next.js PWA. 모바일 우선.
> - **백엔드 (FastAPI)** — 다섯 단계 파이프라인이 핵심.
>   `인테이크 → 프레이밍 → 실행 → 검증 → 전달`
>   - 인테이크: `/messages` 등으로 요청 수신
>   - 프레이밍: 지식으로 답할지 · 실제 실행이 필요한지 분기 + 작업별 도구 라우팅
>   - 실행: 계획·행동·확인 loop, 갈림길에서 결정·안전 모드 승인
>   - 검증: "이렇게 확인하겠다" 약속을 실제 돌려 관측 → 관측 = 판정
>   - 전달: 리포트 생성 + 지식/스킬 반영
> - **저장소** — PostgreSQL (사실·상태·감사) · pgvector (임베딩) · NetworkX (지식 그래프). 파이프라인 전 단계가 여기 읽고 씀.
>
> **하단 부가 설명 세 상자** — 청중이 눈으로 훑는 것으로 충분, 짧게 짚기.
> - 실행 단계가 부르는 **답변 LLM 은 사용자 선택** (API 키형 openai/anthropic/ollama 또는 CLI 워커 claude code/codex/opencode)
> - **커넥터** 는 인테이크로 자동 유입 (GitHub · Slack · Discord · Notion · Email)
> - **로그인은 Supabase**, 임베딩도 사용자 등록
>
> 실행 엔진 · 라우팅 · 안전 가드레일 · 기억 네 개념이 이 다섯 단계 안에 다 녹아있어요.

### 11. 남는 것 — 지식 · 스킬

> 작업이 끝나도 시스템에 **두 갈래 자산** 이 남아요. 오른쪽 두 이미지가 실제 화면.
> - 위 **지식** — 사실. 결정 답안·관찰 메모·거절 패턴이 하나의 그래프로. 반복되면 표준 개념으로 승격. 다음 요청이 자동으로 인용.
> - 아래 **스킬** — 방법. 반복되는 절차가 재사용 자산으로 승격. 다음엔 처음부터 짤 필요 없음.
>
> 검색은 **세 갈래 결합** — 의미·키워드·그래프 이웃을 합쳐 근거를 뽑아냅니다.
>
> 잘못 학습한 노드는 지식 화면에서 한 클릭 **철회** → 30 초 안에 **되돌리기** — 사실을 정정할 창문이 있어요.

### 12. 어디서든, 무엇과도

> 웹 기반이라 설치 없이 브라우저만 있으면 데스크톱·모바일 같은 경험.
> 쓰던 도구를 그대로 연결 — GitHub, Slack, Discord, Notion, Email 같은 것들. 대부분 한 번 로그인이면 됩니다.

### 13. 라이브 데모 cue

> (app.bsvibe.dev 로 전환 — 가능하면 라이브, 어려우면 녹화)
>
> 다섯 흐름.
> 1. **요약** — 작업 중 / 결정 대기 / 지난 작업 한 화면
> 2. **다이렉트** — 입력창에 한 줄 → "전송됨, 작업하고 있어요"
> 3. **전달물 리포트** — 요청 → 만든 것 (파일 inline) → 어떻게 확인했나 → 변경 코드
> 4. **지식** — 학습된 지식 그래프 시각화
> 5. **철회** — 잘못 학습한 노드 한 클릭 → 30 초 되돌리기 토스트
>
> (한 흐름당 15–25 초.)

### 14. Closing

> 감사합니다. 질문 받겠습니다.

|---|---|---|
| **기술** | 왜 streamlit 안 쓰고 Next.js? | 모바일 PWA + 다국어 + 로그인 모두 필요. streamlit 으로는 운영 product 불가 |

| **기술** | 한국어 질문 ↔ 영문 문서 검색은 잘 되나요? | bge-m3 라는 멀티링구얼 임베딩 모델 씁니다. 100+ 언어 학습돼서 같은 의미 한국어/영어 사이 유사도 갭이 절반으로 |
| **기술** | 로그인은? | Supabase 가 토큰 발급, bsvibe 백엔드가 검증. 소셜 로그인 (Google, GitHub) 또는 이메일/비밀번호 |

| **품질** | 잘못된 학습을 되돌리면 이전 답변은? | 새 검색부터 그 노드 제외. 이전 결과 리포트들은 그대로 (감사 추적용) — "이때는 이렇게 답했다" 가 보존. 무덤만 추가 |
| **로드맵** | 출시는 언제? | 현재 자체 호스팅 베타, 한 달 안에 외부 사용자 5명 모집 close beta 예정 |
