# 발표자 노트 (BSVibe · 최종 발표)

청중: 메타코드 부트캠프 — 학우 + 강사. **기술 용어 최대한 풀어** 친근한 톤. 전문어가 꼭 필요하면 한 번씩 풀어 설명.

**총 시간**: 전체 20–25분 (발표 15분 + Q&A 5~10분). 슬라이드 16장.

용어 가이드 (슬라이드 / 노트 / 데모 통일 — PWA i18n `messages/ko.json` 의 공식 한국어 번역 사용):

## 슬라이드별 멘트

### 1. Cover

> 안녕하세요. **BSVibe** 의 김동휘입니다. 한 줄 태그라인이 곧 발표 메시지예요 — "믿음이 아닌, 증명."

### 2. 한 사람이, 여러 제품을

> 1인 회사를 운영하면서 제가 겪은 진짜 비용은 작업 자체보다 **머릿속 정리** 였어요.
> - 같은 결정을 두 번, 세 번 다시 내리고
> - AI 가 만든 결과를 처음부터 다시 확인해야 하고
> - 잡일이 진짜 일을 가립니다.
>
> "AI 가 결과를 믿을 수 있게 돌려주기만 해도 시간이 진짜 줄어든다" 가 출발점이었어요.

### 3. BSVibe 가 답하는 한 줄

> 그 문제에 대한 답이 이 한 줄입니다.
> **한 줄 던지면 AI 가 일하고, 스스로 확인하고, 사람이 읽을 수 있는 근거와 함께 돌려준다. 한 번 바로잡으면 같은 실수는 두 번 없다.**
>
> 차별점 세 가지 — 검증된 결과 / 같은 실수는 한 번만 / 혼자서 여러 제품.

### 4. 어떻게 작동하나요

> 네 단계예요.
>
> 1. **던지세요** — **다이렉트** 버튼으로 한 줄. 메일이나 GitHub 이슈가 들어와도 자리에 없는 동안 시작돼요.
> 2. **AI 가 일합니다** — 계획, 실행, 확인을 반복. 진짜 갈림길에서만 물어보고, 답을 받으면 그 자리에서 이어갑니다.
> 3. **근거를 냅니다** — "끝났다" 는 그냥 받아들이지 않아요. "이 작업은 이렇게 확인하겠다" 가 데이터로 강제됩니다.
> 4. **기억합니다** — 한 번 바로잡은 것이 쌓여서, 다음부터 같은 실수는 알아서 피해요.

### 5. 요약 — 작업 한눈에

> 첫 화면이 **요약** 이에요. **운영 콘솔이 아니라 사람이 말하듯 설명하는 현황판**.
>
> 세 줄로 정리됩니다 — 지금 작업 중, 결정 대기 (갈림길에서 올라온 안건 + 밖으로 내보내기 전 승인 대기), 지난 작업 (끝난 일과 전달물 시간 순).
>
> 처리 안 된 것이 모두 한 화면에 모이는 게 핵심.

### 6. 전달물 리포트 — 유리상자

> 결과는 한 장 짜리 **전달물 리포트** 로 옵니다. 다섯 블록 — 헤더 / 요청 / 만든 것 / 어떻게 확인했나 / 변경 코드.
>
> 강조 포인트: **"만든 것"** 이 진짜 산출물 — 만든 파일의 내용이 곧장 화면에 보입니다. 그리고 **"어떻게 확인했나"** 가 핵심 — 사전에 "이 작업은 이렇게 확인하겠다" 약속을 해두고, 그 약속을 실제로 실행한 결과를 보여줍니다. 확인 없이 통과라고 못 박는 길이 코드 자체에서 막혀 있어요.

### 7. 결정

> 갈림길은 두 종류예요.
> - 답이 정해진 갈림길 — AI 가 알아서 끝까지 진행
> - 취향·범위·방향 같은 사용자만 정할 수 있는 갈림길 — 그때만 올라옵니다
>
> 중요한 부분 — AI 가 단순히 "어떻게 할까요?" 라고 묻기만 하는 게 아니라 **답안 후보를 먼저 만들어서 같이 제시** 해요. 사용자는 그 중 하나를 고르거나, 마음에 안 들면 "직접 입력" 으로 답할 수 있어요.
>
> 답하는 순간 그 자리에서 이어가요 — 다른 화면 옮길 필요 없음. 그리고 그 선택은 **결정 답안** 으로 기억돼서 다음 비슷한 케이스에 자동 재사용됩니다.

### 8. 안전 모드

> 푸시 · 머지 · 메일 발송 같은 **되돌리기 어려운 작업** 은 승인 전엔 밖으로 나가지 않아요.
> 안전한 작업은 자동, 위험한 것만 보류 — 요약 화면의 결정 대기 줄에 모입니다. 사용자가 진짜 신경 써야 할 결정에만 시간을 쓰도록.

### 9. 쓰던 LLM 도구를 그대로

> 흥미로운 부분 하나. bsvibe 는 LLM 을 자체 제공하지 않고, **사용자가 이미 쓰는 도구** 를 그대로 결합합니다.
>
> 지원 도구 — Claude Code, OpenAI Codex, OpenCode. 사용자 컴퓨터에서 한 줄 명령으로 작은 도우미를 띄우면 그 도우미가 bsvibe 와 연결되고, 받은 작업을 사용자 컴퓨터의 도구로 실행해요.
>
> 효과:
> - 사용자가 이미 쓰던 구독·세팅이 그대로 살아있음
> - bsvibe 가 LLM 비용을 따로 받지 않음 (사용자가 이미 내고 있는 거니까)
> - 도구마다 강점이 다르면 작업 종류별로 도우미를 여러 개 띄울 수 있음
>
> 한 줄로 정리 — **bsvibe = 작업 배분 + 결과 확인 + 기억. LLM 선택은 사용자의 몫.**

### 10. Under the hood

> 보이지 않는 곳에서 돌아가는 네 가지 — 실행 엔진, 비용 최적 라우팅, 안전 가드레일, 기억·개인화. 결과만 보이고 나머지는 안에서 돌아갑니다.

### 11. 안에서 어떻게 굴러가나 (내부 구조)

> 개념만 말하면 부족해서 실제 구조를 한 장으로 보여드릴게요.
>
> 세 층으로 나뉩니다.
> - **프론트** — Next.js 로 만든 PWA. 모바일 우선. 사용자가 보는 화면은 요약 / 결정 / 지식 / 리포트.
> - **백엔드** — FastAPI + 백그라운드 워커. 파이프라인이 다섯 단계로 흐릅니다 — 인테이크, 프레이밍, 실행, 검증, 전달.
> - **저장소** — PostgreSQL 가 사실과 상태와 감사 로그, pgvector 가 의미 검색용 임베딩, NetworkX 가 지식 그래프.
>
> 밑에 한 요청이 지나가는 여섯 단계가 있어요. 다이렉트 한 줄이 어떻게 리포트가 되고, 어떻게 지식 그래프에 반영되는지 이 여섯 줄로 파악할 수 있습니다.
>
> 이 흐름의 3~4단계 (실행·검증) 가 다음 슬라이드의 기술 스택과 곧장 연결돼요.

### 12. 지식 그래프

> "기억합니다" 의 실체. 사용자의 모든 결정과 AI 의 모든 관찰이 **하나의 지식 그래프** 로 쌓입니다.
> - 날 것의 관찰 (관찰 메모) 이 일정 횟수 반복되면 표준 개념으로 승격
> - 결정과 거절된 접근이 따로 인덱싱돼 다음 작업에 자동 인용
> - **세 갈래 검색** — 의미 검색 + 키워드 검색 + 그래프 이웃 — 을 합쳐서 답변 근거로 사용
>
> 잘못 학습한 노드는 **지식** 화면에서 한 클릭으로 **철회** — 30 초 안에 **되돌리기** 가능.

### 13. 어디서든, 무엇과도

> 웹 기반이라 설치 없이 브라우저만 있으면 데스크톱·모바일 같은 경험.
> 쓰던 도구를 그대로 연결 — GitHub, Slack, Discord, Notion, Email 같은 것들. 대부분 한 번 로그인이면 됩니다.

### 14. 기술 스택

> 프론트는 Next.js PWA, 백엔드는 FastAPI + PostgreSQL, 벡터 검색은 pgvector, 그래프는 NetworkX. 여기까지는 표준.
>
> 강조하고 싶은 부분은 **답변 생성이 추상화된 인터페이스** 라는 점이에요. 사용자가 아래 중 원하는 걸 골라서 씁니다 — 둘 다 설정해야 하는 게 아니라 **선택**이고, 여러 개 등록해서 작업별로 라우팅할 수도 있어요.
>
> - **옵션 1** — API 키를 등록해서 일반 LLM 을 붙임 (openai · anthropic · ollama 등). LiteLLM 기반이라 provider 는 뭐든 됩니다.
> - **옵션 2** — 앞 슬라이드에서 본 것처럼 내 컴퓨터의 CLI 워커 (claude code · codex · opencode) 를 붙임.
>
> **임베딩도 똑같이** — 사용자가 provider · 모델을 등록. 특정 모델을 강요하지 않아요.
>
> 즉 bsvibe 는 dispatch 메커니즘만 제공하고, 선택은 100% 사용자의 몫. 로그인은 Supabase.

### 15. 라이브 데모 cue

> (app.bsvibe.dev 로 전환 — 가능하면 라이브, 어려우면 녹화)
>
> 다섯 흐름.
> 1. **요약** — 작업 중 / 결정 대기 / 지난 작업 한 화면
> 2. **다이렉트** — 입력창에 한 줄 → "전송됨, 작업하고 있어요"
> 3. **전달물 리포트** — 요청 → 만든 것 (파일 inline) → 어떻게 확인했나 → 변경 코드
> 4. **지식** — 학습된 지식 그래프 시각화
> 5. **철회** — 잘못 학습한 노드 한 클릭 → 30 초 되돌리기 토스트
>
> (한 흐름당 15–25 초.)

### 16. Closing

> 감사합니다. 질문 받겠습니다.

## Q&A 대응표

| 질문 유형 | 예상 질문 | 답안 핵심 |
|---|---|---|
| **기술** | 왜 streamlit 안 쓰고 Next.js? | 모바일 PWA + 다국어 + 로그인 모두 필요. streamlit 으로는 운영 product 불가 |
| **기술** | LLM 모델·도구는 어떻게 골라요? | 작업 공간이 (도구, 모델) 정책 매트릭스를 가짐. 작업 종류 + 비용 가중치로 자동, 사용자가 덮어쓰기 가능 |
| **기술** | claude code / codex / opencode 동시에 띄울 수 있나요? | 네. 사용자 컴퓨터에서 도우미 여러 개 띄우면 백엔드가 capability 별로 배분 — 같은 작업을 여러 도우미에 동시 race 도 가능 |
| **기술** | "세 갈래 검색" 이 뭔가요? | 의미 임베딩 검색 + 키워드(BM25) 검색 + 그래프 이웃 탐색 — 각각의 랭킹을 합쳐 (RRF) 최종 top-K. 셋의 약점을 서로 보완 |
| **기술** | 한국어 질문 ↔ 영문 문서 검색은 잘 되나요? | bge-m3 라는 멀티링구얼 임베딩 모델 씁니다. 100+ 언어 학습돼서 같은 의미 한국어/영어 사이 유사도 갭이 절반으로 |
| **기술** | 로그인은? | Supabase 가 토큰 발급, bsvibe 백엔드가 검증. 소셜 로그인 (Google, GitHub) 또는 이메일/비밀번호 |
| **제품** | Notion AI · Granola 와 뭐가 달라요? | 메모/노트 도구가 아니라 **AI 가 실제 작업을 하고 그 결과에 근거가 붙는** 도구. 결과 리포트가 핵심 |
| **제품** | 진짜 1인이서 만든 거예요? 운영 비용은? | 네. Mac Mini 자체 호스팅 + Vercel free + Supabase free + 도우미가 사용자 컴퓨터의 LLM 쓰니까 LLM 비용도 별도 없음 → 월 ~10달러 |
| **제품** | 사용자 데이터는요? | 작업 공간 단위로 격리. 모든 메모와 그래프는 사용자 본인 데이터. 다른 작업 공간 접근 불가 |
| **품질** | "확인" 이 LLM 판정이면 그것도 환각 가능하지 않나요? | 맞아요. 그래서 검증 약속이 **실제로 실행 가능한 검사** 를 강제 — `pytest` exit code · `ruff` 통과 · 외부 API 응답 같은 결정적 신호. LLM 판정은 보조 |
| **품질** | 잘못된 학습을 되돌리면 이전 답변은? | 새 검색부터 그 노드 제외. 이전 결과 리포트들은 그대로 (감사 추적용) — "이때는 이렇게 답했다" 가 보존. 무덤만 추가 |
| **로드맵** | 출시는 언제? | 현재 자체 호스팅 베타, 한 달 안에 외부 사용자 5명 모집 close beta 예정 |
| **로드맵** | 가격은? | 보류 — 1인이 여러 제품 굴리는 데 맞는 단순한 가격 다듬는 중. 지금은 무료 |
